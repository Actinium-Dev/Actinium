# 末地传送门渲染

## 平视门面时星空覆盖场景

GreedyCraft2-T 使用 `ComplementaryShaders_v4.7.2` 时，在激活的末地传送门附近沿门面高度转动视角，偶尔会出现覆盖画面左下角的 1024×1024 星空方块。合成器绑定离屏 framebuffer 后，设置绘制缓冲区时会触发待绘制的方块实体批次刷新。批次重新绑定世界 framebuffer 后，合成器的全屏三角形会把星空写入场景。

合成器现在先刷新待绘制的批次，再切换到离屏 framebuffer。合成期间暂停批次刷新，恢复光影 pass 后再继续。离屏 OpenGL 回归测试在旧实现中复现了场景像素被覆盖的问题，修复后确认场景像素保留且合成纹理按帧更新。2026-11-22 的 GreedyCraft2-T 复测日志显示，修复版的合成程序使用独立的 framebuffer。

## 门面转出画面时掉帧

### 触发条件与根因

启用光影包，在距离末地传送门数格的位置朝门面方向转动视角。门面刚完全离开画面时，方块实体仍可能位于已收集的区块内，主场景仍会调用传送门渲染器。旧的网格构建只处理近裁剪面与齐次坐标的除数下限，因此 CPU 仍然细分视口外的门面，并逐层生成和提交顶点。Spark 采样 `BM7yaLTciC` 中，传送门渲染占客户端线程采样的 51.3%。

### 修复与验证

光影主场景按当前投影检查门面的四个角。四角全部位于同一个视口侧平面外时，跳过该面的细分；没有剩余三角形时，不提交传送门绘制。跨越视口边缘的门面保留原几何，阴影 pass、无光影路径和无世界的合成覆盖仍使用原有规则。

回归测试中，旧实现对完全离开画面的门面仍生成 128 个三角形，修复后生成 0 个；跨边缘时几何保持一致。`gradlew check build --offline --no-daemon` 通过。2026-11-20，用户在 `1.12.2-Cleanroom` 实例使用 `MakeUp-UltraFast-9.4c` 复测后确认问题解决。
