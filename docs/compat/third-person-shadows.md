# 第三人称相机与阴影坐标

2026-11-26，基于 `992ab674` 修复。

## 根因与处理

Minecraft 1.12.2 的原始 model-view 以插值后的实体脚部位置为输入原点，矩阵中已经包含眼高、第三人称镜头距离和视角变换。相机位置必须由该矩阵的逆变换求得，再加实体脚部世界坐标。原实现把逆变换结果加到实体眼睛位置，第三人称下重复增加眼高。

主地形和 `gbufferModelView` 原先使用实体眼睛原点，`cameraPosition` 却包含第三人称位移。用 `gbufferModelViewInverse` 重建位置并加上 `cameraPosition` 时，会额外加入相机偏移。修复后主地形、相机 uniform、阴影地形、实体与方块实体的阴影绘制使用实际相机原点，矩阵与顶点坐标一起调整。

主视图 CPU 裁剪平面原先保留原始矩阵的平移，而 viewport 已减去实际相机位置，导致重复应用位移。修复后原版实体裁剪继续使用完整矩阵，viewport 裁剪和 raster occluder 使用相机相对矩阵。advanced / safe-zone 阴影裁剪也使用相同参考点，避免重复计算眼高或第三人称位移。

相机矩阵与裁剪数据在捕获视图时更新并复用。逐区块包围盒测试不新增矩阵求逆或对象分配，地形 pass 复用缓存矩阵。

## 验证记录

修复前已用本地 Minecraft 字节码和 JOML 数值实验确认重复眼高、世界坐标重建偏移与裁剪误判。自动化回归覆盖相机位置、主视图和阴影坐标往返以及世界包围盒的可见性。

JDK 25 的独立分配探针在预热后执行 1,000,000 次相机与裁剪数据更新，当前线程累计新增分配为 0 字节。该探针直接调用生产数学类，未包含 viewport 快照、游戏渲染与 GPU 提交。`gradlew.bat check build --no-daemon` 已通过，使用 Java 25、D 盘 Gradle 缓存和临时内存限制。相机、裁剪与矩阵 uniform 的 6 项测试均通过，其中 5 项为本次新增。游戏画面与 FPS 尚未实测，以下场景需要实机确认。

## 实机验证方案

1. 使用 BSL 或 Complementary，记录版本与预设，固定时间、天气、渲染距离和阴影距离。在有树木、高墙、台阶及长阴影的同一位置循环切换第一人称、背面第三人称和正面第三人称。阴影接触点应保持贴合几何体。
2. 在第三人称靠近墙面，让碰撞检测改变镜头距离，转动水平和垂直视角。检查视野边缘、阴影覆盖边缘的方块、实体与方块实体，确认没有随镜头距离变化的漏影或消失。
3. 对照 advanced、safe-zone 与 distance 阴影裁剪模式，覆盖玩家和坐骑阴影。快速反复切换 F5，再静止观察，记录持续错误和短暂列表更新的区别。
4. 检查第一人称行走摇晃、潜行、骑乘、水面上下切换以及手持物遮挡。使用 Distant Horizons 时补充近景与 LOD 交界，并回归传送门嵌套视图。
5. 关闭光影重复边缘区块、实体可见性检查，验证原版视锥与 Celeritas viewport 的结果一致。
6. 性能比较使用同一 Java、后端、GPU、世界、光影预设和已构建区块。预热后分别对基线与修复版本进行三轮等长的静止、转动镜头与 F5 切换，记录帧时间中位数、P95、区块搜索及阴影 setup 耗时。正确裁剪可能改变实际绘制数量，比较时同步记录可见区块数。
